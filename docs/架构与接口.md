# 架构与接口

## v2 实践工作台增补（2026-10-03）

运行架构继续使用 Next.js、Route Handlers + Zod、SQLite WAL 与独立 Node worker。研究、评测、问题、阶段审阅和分享记录为本地台账操作，不提交媒体 worker 任务，不自动调用模型或第三方 Skill。新增实现的实际验收以 [验证记录](验证记录.md) 为准。

### 实践记录模型

`work_records` 保存当前完整 JSON 与最初规范化的创建内容；`work_record_versions` 按 `(record_id, revision)` 保存完整版本快照。记录包含 UUID、类型、状态、来源、项目关联、目标/输入/通过条件/原始观察/行动/证据、可选人工评测与媒体复测字段。

记录和项目各有独立 revision。记录保存项目 revision 与内容指纹；读取时比较作品创作内容，生成 `stale` 提示。记录普通编辑保留原项目依据；只有关联变化或明确 `reconfirmProjectRevision` 才更新锚点。确认参数必须等于当前项目版本，否则返回冲突。指纹包含创作内容与人工镜头卡，不以媒体任务状态更新自动宣布内容通过。

创建时传客户端 UUID：相同 ID 与原始创建内容重提返回既有记录，即使记录后续已编辑也不覆盖；同 ID 用于不同创建内容返回 409。历史保存和当前更新在事务中完成，PATCH 与 DELETE 需当前记录 revision。

删除项目时，先保存旧关联版本，再将当前记录的 `projectId/projectRevision/projectFingerprint` 置空、增加 record revision 并留新版本；实践内容与旧历史保留。单独删除记录会移除该记录及其版本历史，不是软删除，建议先导出。

### 新增 HTTP 契约

仍为单用户本地工具，使用现有本机 Host 与同源请求检查，不提供多用户公共鉴权。

| 方法与路径 | 请求 | 响应与约束 |
|---|---|---|
| GET `/api/records` | 无 | `WorkRecord[]`，含当前关联的需复核状态 |
| POST `/api/records` | `WorkRecordInput + id(UUID)` | 首次 201，相同创建内容 200 原记录；ID 异内容复用 409 |
| GET `/api/records/:id` | UUID | 当前 `WorkRecord`；不存在 404 |
| PATCH `/api/records/:id` | 完整 `WorkRecordInput + revision`；可选 `reconfirmProjectRevision` | 新记录；旧 record revision 或复核期间 project revision 改变为 409 |
| DELETE `/api/records/:id?revision=N` | 当前 record revision | `{ok:true}`；缺 revision 拒绝、过期 409；删除该记录及其历史 |
| GET `/api/records/:id/history` | UUID | 完整版本数组，按 revision 倒序；不宣称历史项目媒体本身可回滚 |

GET `/api/records/export` 下载当前记录、项目和方法元数据的 JSON 档案；GET `/api/records/:id/export` 下载 Markdown，加 `?format=history` 下载完整版本 JSON。三个下载都从当前 SQLite 读取，返回附件及 no-store，应用本机 Host/Origin 校验；没有独立公开发布接口或自动发送。对外分享前需检查材料权限与敏感内容。

### 人工评测、镜头卡与媒体卡

- `evaluation`：caseId、model、promptVersion、completion(pass/fail/unknown)、score、factualErrors、interventions、latencyMs、tokens、cost、currency、costSource。可选数字为 `null` 时表示未知；真实零值保留。有费用值必须说明依据，但服务端不自动核验账单真实性或计费价格。
- `shot.continuity`：characters、props、entryState、exitState、dialogue。均为人工文本记录；准确台词与合成 narration 分开，前者不额外触发配音或视频生成。新字段可选以兼容旧项目。
- `media`（仅 issue/review）：episode、stage、timeStart/timeEnd、shotId、issueType、audioStrategy、repairScope、localCheck/adjacentCheck/fullCheck、credits、creditsSource、attempts。已填区间终点必须大于起点；积分有值时来源必填，尝试次数及候选/返工口径人工说明。声轨策略是记录，不是远端静音或剪辑命令。
- 三层复验为 pending/pass/fail，状态记录与实际媒体执行分开。归档需要实际观察；评测归档另需模型、case、通过条件和明确 pass/fail。归档允许失败结果，不代表内容验收通过。

### 编码区间与问题定位

新本地合成在每镜编码后读取媒体时长，累计保存 `render.timeline[{shotId,start,end}]`，包含旁白延长与帧舍入。质量页使用该区间定位问题并带入记录；时长保留两位小数，拼接与帧舍入可能有偏差，边界以播放器复核为准，不宣称帧精确外部源片追踪。

旧成片无 timeline 时，`projectTimeline` 只从计划 shot.duration 生成区间并标 `plan`；有编码区间为 `render`。配音会延长镜头，所以 plan 不能当成真实成片时间。作品后续编辑时，当前镜头卡与旧片还需核对。该定位适用于漫序自己的静帧合成，不提供外部视频上传、剪辑、自动停用原声、口型检测或自动视觉审阅。

## 课程 MVP 与继续复用的基础架构

以下内容来自原课程版本，仍说明现有制作与任务流程；原始时间与验收记录没有被 v2 改写。

## 进程与状态
网页和 worker 使用同一个 SQLite 数据库。任务按提交顺序串行消费，避免个人电脑同时承载多个视频编码。项目编辑通过 revision 实现乐观锁，任务使用部分唯一索引保证同一项目只有一个 queued/running 任务。

API 使用幂等键恢复已创建任务。worker 保存产物时在数据库事务中重新检查任务是否仍为 running；取消后迟到的模型结果不能覆盖新编辑。最终产物与 succeeded 状态在同一事务提交。

刷新仅 GET 已有项目，不创建任务。浏览器的 disconnected 状态不代表后端失败。

## HTTP 契约

所有写请求只接受本机 Host 和匹配 Origin；本课程版本是单用户本地工具，不提供公共服务鉴权。

| 方法与路径 | 请求 | 响应 / 说明 |
|---|---|---|
| GET `/api/projects` | 无 | `Project[]` |
| POST `/api/projects` | `ProjectInput` 或 `{template:"demo"}` | 201 `Project` |
| GET `/api/projects/:id` | 无 | `{project,job}`，job 为最新任务或 null |
| PATCH `/api/projects/:id` | `ProjectInput + revision` | 更新后 Project；过期 revision 返回 409 |
| DELETE `/api/projects/:id` | 无 | `{ok:true}`；有活动任务返回 409 |
| POST `/api/projects/:id/jobs` | `{kind:"script"|"images"|"render"}` + `Idempotency-Key` | 202 Job；重复键返回原任务；键跨项目复用拒绝 |
| POST `/api/projects/:id/images` | multipart `shotId,revision,file` | 图片解码/重编码后返回 Project；10 MB 上限 |
| GET `/api/jobs/:id` | 无 | Job |
| POST `/api/jobs/:id/cancel` | 无 | Job；worker 停止处理，保留已完成素材 |
| GET `/api/assets/:project/:file` | 可选 Range | 文件流，206 支持拖动播放；不合法范围 416 |
| GET `/api/settings` | 无 | 只返回配置/服务状态，不回传凭证 |

错误统一为 `{error:{code,message}}`；无原始堆栈、供应商响应或密钥。

## 媒体流水线

1. 固定项目快照，拒绝缺画面的合成。
2. 将每镜画面裁切到目标比例，为字幕生成透明覆盖层。
3. macOS `say` 或配置的 TTS 产生旁白；检测音频时长。
4. 镜头时长取计划时长与配音长度的较大值。
5. FFmpeg 实现平滑推拉、覆盖字幕，编码 H.264 / AAC。
6. 合并片段并写入 MP4 `faststart`，输出独立 SRT。

此流程只处理静帧动态漫画，不包含图生视频、角色骨骼动画或唇形同步。
