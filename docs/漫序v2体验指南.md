# 漫序 v2 体验指南

更新日期：2026-10-03。本文说明当前工作台提供的操作路径；本轮最终验收结果另见 [验证记录](验证记录.md)，不以指南替代实测。

漫序现在是个人 AIGC 产品实践工作台。你既可以制作动态漫画，也可以把研究依据、人工评测、镜头约束、失败问题与复测留在同一个工作区。它没有替你自动跑完全部研究和审片；AI 生成、程序合成和人工判断分别记录。

## 从哪里打开

在本机启动项目后，打开 **[漫序工作台](http://127.0.0.1:3210)**。页面与任务 worker 都要运行；已有项目目录中执行：

```bash
npm ci
npm run dev
```

首次配置、系统条件和模型接入见 [README](../README.md#快速开始)。手工建立记录、打开原创示例、编辑镜头和本地导出不需要模型 Key；真正的 AI 剧本与图片生成需要实际可调用的授权与配置。

这是你电脑上的本地单用户产品。`127.0.0.1` 不是别人可用的共享链接；本轮新迭代尚未推送 GitHub，没有部署完整公网服务。GitHub 公开源码与网站在线可用分别核查。

## 第一步：留下一项研究，而不是只收藏链接

进入「研究与需求」，点击「新建记录」。填写一个具体任务，例如“如何让创作者只修改一个有问题的镜头”。这是可尝试的研究题目，不是已有访谈结论。

把任务目标、输入材料、通过条件、观察和行动分别写下。证据可以是公开链接，也可以是本机文件名、观察日期、版本或镜头区间；这里填写文件名不会自动上传文件。

在观察里区分可见事实、推断与未知。没有实际使用竞品，就写资料研究；没有用户访谈，不把自己的想法写成用户需求。选择资料性质“个人记录”“公开资料”或“教学示例”，保存后可关联创作项目、继续编辑、搜索或导出。

「使用教学模板」只帮助理解字段。模板没有调用模型，也不代表完成过真实研究；保留教学标识。

## 第二步：用相同任务比较模型或 Prompt

进入「模型评测」，建立评测记录，先填写样例 ID、输入、目标与通过条件，再填写实际模型和 Prompt 版本。将真实原始输出和逐项判断保存；另一个模型或版本应使用同一任务与标准，才有合理的对照基础。

“同任务对照”按样例 ID 展示已填记录。如果同一个 ID 下目标、输入或标准不同，页面会提示条件有差异；不要把表格并排误认为控制变量已经成立。

完成判断可为通过、失败或未判定。评分、事实错误、人工干预、耗时、Tokens 和费用都由你录入，**不是页面自动测得**。未知留空，不填零；真实测得零次错误和不知道有没有错误是两回事。费用有值时填写币种和可核对的计费依据，填依据不表示系统已经核验账单。

失败结果也值得保存。归档前需要真实观察、通过条件、模型和任务编号及明确通过/失败判断；“已归档”表示记录结束，不表示模型达标。一次样例不能证明一个模型普遍更好。

## 第三步：制作作品，并写清每镜约束

进入「创作工作室」，可以打开原创示例，或创建自己的作品。沿原流程填写故事、审阅角色与分镜、修改旁白、逐镜上传画面，再进入配音成片。AI 生成需要已配置的服务；点击某阶段不会自动承担所有后续生成。

在分镜编辑器展开 **「角色、道具与连续性镜头卡」**，填写：

- 本镜角色与道具。
- 镜头起始状态与结束状态。
- 准确台词，供审阅使用。

下方可看上一镜结束与下一镜起始记录，便于你检查道具、位置、动作和信息是否衔接。修改后保存，刷新再打开可以继续工作。

这里是人工镜头卡。文字写“同一个人”不等于画面已经锁脸；准确台词字段不会自动产生独立角色配音，实际合成仍使用上方旁白/台词。当前作品类型为静帧图片配镜头推拉、旁白字幕的动态漫画，不是有连续表演与口型的真人视频模型生成。

## 第四步：从问题时间回到镜头，再完成复测

进入「质量与复测」。项目检查卡先提示结构和素材情况，**结构完整不等于内容审核通过**。需要确认脚本、分镜或交付时，点击「新建阶段审阅」，关联作品，写下实际检查和结论。

成片出现问题后，在「从问题时间，回到源镜头」选择项目、输入发生的秒数：

- 新本地合成有编码镜头区间，可带入对应镜头和问题时间。
- 旧片没有区间时只显示计划。配音可能延长镜头，计划不能当真实成片时间；切点精度约 0.01 秒，仍需播放器复核。
- 项目后来修改过，当前镜头卡与旧成片还要逐项核对。

点击「带入问题记录」后补齐集/片段、问题阶段、类型、声轨建议、返工范围和证据。界面不会因为你选“静音”就执行停用声轨，也不会自动剪辑、视觉检查或重生成。实际修复应在创作流程或你使用的媒体工具中完成，再回来记录结果。

分别填写 **局部、相邻镜头、全片/整集** 的通过、失败或待检查，并写实际观察。只看局部的修复不能自动称整片通过；尚未看的范围保持待检查。

如果你记录积分或生成尝试次数，说明来源、是否包含候选和返工、能否对应镜头。同一笔不要重复填。积分不是现金；没有真实金额依据就保持未知，不按 Token 或套餐价格自动换算。

## 第五步：更新依据，并留下可分享的版本

实践记录可关联作品。作品内容变化后，原记录会提示 **「需复核」**。补备注、改标题或改状态不会自动消除提示，因为这不证明你重新检查了作品。

实际复查后，在编辑窗口勾选“我已重新检查当前项目内容”，再保存为当前作品版本的依据。如果期间作品再次修改，应重新载入并检查，而不是覆盖新版本。

打开记录详情的「查看原始版本」，可以查看当时的原始观察、行动、证据数量和关联版本，再「导出版本档案」。历史快照不表示当前作品通过审核，也不能补造升级前从未保存的修改。

在「知识分享」新建记录，整理任务背景、证据、有效方法、失败与未知项，导出 Markdown 继续编辑。总览的「导出实践档案」用于备份整个工作区；导出不等于公开发布，分享前检查公司材料、第三方信息与素材权限。

删除作品会保留实践记录及其历史、解除关联。单独删除实践记录则移除该记录和历史，所需内容先导出备份。

## 两条项目来源不要混在一起

漫序的研究、评测、人工确认、局部返工与质量复验方向来自用户提供的快看漫画实习经历，是实习之后的个人沉淀实现。2026-09-22 的课程 MVP、原创示例和当时验证历史仍保留；当前工作台不代表快看内部产品或公司业绩。

**《下次做给我吃》是在另一个平台制作完成的，平台未由用户指名。** 漫序这里只承接其角色/道具约束、声轨复核、局部修复和交付方法。六集、403 秒、124 笔视频生成、11,460 积分均为外部实践公开复盘口径，不是漫序的产出、调用或成本；本轮也没有逐片重新验证该短剧。

六项开源 Skill 和外部项目帮助解释方法，但不意味着工作台已接入它们的全部能力。当前没有自动批量模型评测、GPU 锁脸、自动视听审片、外部视频上传剪辑、自动声轨静音或动态文字透视修复。
